## 阶段 1.5：风格参数探索 ✅ 已完成

**问题：** 现有4种风格存在色相偏移（如肤色变红、变黄），原因是 RGB 空间色阶分离会破坏色相。

**方法：** 用 Python 批量生成约20种参数变体，用户目视选出每种风格最佳参数，然后固化到工具中。

**最终确定的4种风格参数：**

| 风格 | 算法 |
|------|------|
| 写实 | bilateral(r=2) → RGB色阶(6级) |
| 卡通 | bilateral(r=3) → HSV色阶(H=12,S=4,V=6) → Sobel自适应暗化描边(阈值80, ×0.35) |
| 抽象 | gaussian(r=2) → pixelate(30px) → HSV色阶(H=8,S=3,V=4) |
| 复古 | gaussian(r=2) → 暖色偏移 → HSV色阶(H=12,S=4,V=6) → sat×0.70 |

## 阶段一：MVP — 验证核心算法（目标：能用就行）

**目标：** 跑通"平滑 + 色调分离"管线，人眼判断输出图是否比原图更适合像素化。

### 任务清单

| # | 任务 | 验收标准 |
|---|------|----------|
| 1.1 | HTML 骨架：上传图片 + Canvas 显示 | 能上传图片并在页面上显示 |
| 1.2 | 色调分离（Posterization）实现 | 滑动级数，图片色彩层次肉眼可见减少 |
| 1.3 | 高斯模糊平滑（先不做双边滤波）| 图片噪点/纹理被平滑，主体轮廓尚存 |
| 1.4 | 下载输出图 | 能把处理后图片保存为 PNG |

### 测试方法

1. 准备 3 张测试图：人物照片、动物照片、风景照片
2. 对每张图：
   - 直接导入"画像素"（或类似工具）→ 截图保存
   - 经本工具处理后导入"画像素" → 截图保存
3. 对比两组截图，人眼判断：色块是否更干净？马赛克感是否减少？

**通过标准：** 3 张中至少 2 张有明显改善 → 假设成立，继续开发。

**失败处理：** 效果不明显 → 回来调整算法参数或核心思路，不进入阶段二。

## 阶段二：加入边缘检测（强化核心差异化功能）

**目标：** 验证"边缘约束平滑"是否比无约束平滑效果更好。

### 任务清单

| # | 任务 | 验收标准 |
|---|------|----------|
| 2.1 | Sobel 边缘检测 + 青色叠加预览 | 边缘线清晰显示在原图上 |
| 2.2 | 阈值滑块 + 实时预览（150ms 防抖）| 滑动阈值，边缘线实时变化 |
| 2.3 | 边缘约束平滑（双边滤波替换高斯）| 平滑不跨越边缘，主体轮廓保留清晰 |
| 2.4 | 确认轮廓 → 执行处理 → 下载 | 端到端流程可用 |

### 测试方法

同阶段一，新增对比组：
- 无边缘约束处理 vs 有边缘约束处理
- 重点观察主体边界是否更清晰

**通过标准：** 有边缘约束的输出，主体轮廓比无约束版本更清晰 → 双边滤波值得保留。

## 测试图片准备

建议准备以下类型各 1–2 张：

| 类型 | 原因 |
|------|------|
| 人物半身照（真实照片）| 最常见使用场景，肤色渐变是最大挑战 |
| 卡通/动漫截图 | 验证对已简化图片是否有帮助或反效果 |
| 动物照片（毛发细节多）| 高频纹理，平滑算法压力测试 |
| 风景/建筑（几何边缘清晰）| 边缘检测效果验证 |

## 风险与退出条件

| 风险 | 退出/调整条件 |
|------|--------------|
| 算法效果不如预期 | 阶段一测试不通过 → 重新评估工具定位或核心算法 |
| 双边滤波性能太差 | 阶段二处理时间 > 10秒 → 降级为高斯模糊 + 边缘锐化替代 |
| 与 AI 工具效果差距太大 | 阶段一对比 AI 卡通化输出 → 考虑专注"离线/可控"差异化而非效果竞争 |
